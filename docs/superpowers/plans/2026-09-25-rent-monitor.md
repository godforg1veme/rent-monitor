# Rent Monitor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать изолированный монитор новых московских объявлений долгосрочной аренды с двумя комнатами, ценой до 70 000 ₽ в месяц и явно нулевой комиссией, с уведомлениями в один привязанный Telegram-чат.

**Architecture:** Четыре независимых HTTP-сборщика (Avito, Cian, Domclick, Яндекс Недвижимость) преобразуют публичные страницы в общий `Listing`. Общие фильтры, межисточниковая дедупликация и SQLite outbox отделяют сбор от Telegram. При ограничении доступа приостанавливается только соответствующий источник. Изолированная systemd-служба развернута отдельно от Jarvis.

**Tech Stack:** Python 3.11+, asyncio, HTTPX `AsyncClient`, aiogram 3.x long polling, aiosqlite, SQLite, TOML, systemd.

**Spec:** [../specs/2026-09-25-rent-monitor-design.md](../specs/2026-09-25-rent-monitor-design.md)

## Global Constraints

- Код публиковать в приватный GitHub `godforg1veme/rent-monitor`; развертывание разрешено отдельным последним указанием пользователя. Изменять только принадлежащие Rent Monitor пути и его systemd-службу; не менять Jarvis, Docker Compose, соседние сервисы или данные.
- Допустимы только редкие запросы к публичным страницам поиска и к публичной карточке объявления для уточнения комиссии. Не использовать вход в аккаунт, cookies, прокси, маскировку браузера, CAPTCHA-solving, непубличные API, страницы профилей, телефоны и переписку. При 401/403/CAPTCHA источник поставить на паузу; 429 уважать `Retry-After` и вводить backoff без учащения запросов.
- Соблюдать один HTTP-запрос одновременно глобально, одну поисковую страницу на источник за цикл каждые пять минут с разнесённым стартом, не более одной страницы карточки на источник за цикл и не чаще одной карточки в минуту; распакованный ответ ограничить 8 MiB.
- Фильтровать только `rooms == 2`, месячную цену `<= 70000` и `commission_status == "none"`. Неизвестные комнаты, цена или комиссия не подходят. Не выводить нулевую комиссию из отсутствия поля.
- Первую успешную выдачу каждого источника считать начальной базой без уведомлений; если источник не ответил успешно или структура не распознана, не фиксировать baseline для него.
- Не сохранять HTML, cookies, полные описания, телефоны, контакты или секреты. Не писать секреты/тела ответа в логи.
- Telegram-токен брать только из systemd credential-файла через `CREDENTIALS_DIRECTORY`; не включать в репозиторий, аргументы процесса, SQLite, логи или переписку. Привязать один личный `chat_id` одноразовым короткоживущим кодом, код после привязки аннулировать.
- VPS использует отдельный systemd unit с `CPUQuota=50%`, `MemoryMax=1G`, `TasksMax=64`, `IOWeight=10` и hardening.
- Полный E2E запускать только из виртуального окружения после публикации всех файлов в GitHub. При дефекте исправление сначала загрузить в GitHub, затем повторить тест с опубликованной версии.

**Интерфейсы:**

```python
@dataclass(frozen=True)
class SearchCriteria:
    city: str
    rooms: int
    max_monthly_price_rub: int
    require_no_commission: bool


@dataclass(frozen=True)
class Listing:
    source: str
    source_id: str
    url: str
```

**Ограничения:** `Listing` не хранит исходный HTML, профиль, номер телефона или полный текст карточки. Секрет читается только при старте из credential directory.

### Задача 2: Реализовать чистые фильтры и межисточниковую дедупликацию

**Файлы:** `src/rent_monitor/core/filters.py`, `src/rent_monitor/core/dedupe.py`.

- [ ] Реализовать `matches_listing(listing, criteria) -> bool`: все три обязательных условия должны быть явно известны и пройдены.
- [ ] Реализовать нормализацию адреса без потери номера дома/корпуса; не нормализовывать адрес через геокодер или сторонний API.
- [ ] Реализовать внутриплощадочную идентичность по `(source, source_id)`.
- [ ] Реализовать межплощадочное совпадение только при точном совпадении нормализованного адреса, числа комнат и цены, а также площади с разницей не более 1 м². При пропуске любого ключевого поля не объединять объявления.
- [ ] Возвращать ключ группы и набор ссылок на источники так, чтобы первое объявление группы могло уведомить один раз, а последующее с другой площадки добавляло альтернативную ссылку без второй обычной нотификации.

**Интерфейсы:**

```python
def matches_listing(listing: Listing, criteria: SearchCriteria) -> bool: ...
def normalize_address(address: str) -> str: ...
def find_duplicate_group(listing: Listing, candidates: Sequence[Listing]) -> str | None: ...
```

**Ограничения:** неизвестная комиссия остаётся неизвестной и не проходит фильтр. Не объединять по одному лишь заголовку, району, метро или приблизительному адресу.

- [ ] Создать таблицы объявлений, групп совпадений, альтернативных source links, состояния источников, метаданных baseline, pairing code/chat binding и очереди уведомлений.
- [ ] Записывать ID всех карточек первой распознанной выдачи как начальный cohort источника независимо от того, проходят ли они фильтр; это не требует скачивать их детали и не создаёт уведомлений. Успешный распознанный пустой результат также завершает baseline.
- [ ] Добавить уникальность `(source, source_id)` и идемпотентное создание notification по ID группы объявления.
- [ ] Предусмотреть операции: `initialize`, `upsert_listing`, `record_baseline_candidates`, `find_duplicate_candidates`, `enqueue_notification`, `claim_pending_notifications`, `mark_delivered`, `record_source_status`, `get_source_statuses`, `set_source_baseline`, `issue_pairing_code`, `consume_pairing_code`, `get_allowed_chat_id`, `bind_chat_id`, `set_paused`.

**Интерфейсы:**

```python
class SQLiteRepository:
    async def initialize(self) -> None: ...
    async def upsert_listing(self, listing: Listing) -> tuple[str, bool]: ...
    async def enqueue_notification(self, group_id: str, listing: Listing) -> bool: ...
    async def claim_pending_notifications(self, limit: int = 20) -> list[Notification]: ...
    async def mark_delivered(self, notification_id: int) -> None: ...
```

**Ограничения:** обновления объявления и постановка его уведомления в очередь должны быть атомарными, чтобы перезапуск процесса не терял находку и не создавал повторов.

### Задача 4: Построить HTTP transport и общий цикл планировщика

**Файлы:** `src/rent_monitor/transport.py`, `src/rent_monitor/core/scheduler.py`, `src/rent_monitor/sources.py`.

- [ ] Создать один `httpx.AsyncClient` с конечными connect/read/write/pool timeouts, повторным использованием соединений и понятным User-Agent приложения.
- [ ] Читать response body потоково и прекращать чтение при превышении 8 MiB уже после распаковки; не сохранять тело в лог/БД.
- [ ] Ввести общий `asyncio.Semaphore(1)` на запрос, throttle карточек отдельно по источникам и ровно один поисковый запрос к источнику за цикл.
- [ ] Раснести четыре источника внутри 300-секундного цикла, чтобы не делать одновременный burst. Для 429 учитывать `Retry-After`, иначе использовать ограниченный экспоненциальный backoff. Не повторять запросы для 401/403/CAPTCHA.
- [ ] Определить единый протокол `Collector.collect(criteria, client) -> CollectionResult` и типизированные статусы `ok`, `degraded`, `paused`, `error`.
- [ ] Планировать до пяти detail pages на источник за цикл и не чаще одной detail page в минуту на источник; лишние кандидаты оставить в ограниченной очереди к следующему циклу.
- [ ] На первой успешно распознанной выдаче фиксировать набор `source_id` как baseline cohort и не отправлять их в outbox. После этого новые ID проходят комиссионный фильтр и дедупликацию; недоступный или нераспознанный источник baseline не получает.
- [ ] Ошибка транспорта/разбора одного источника не прерывает цикл остальных. Повторяющаяся нераспознанная структура переводит только этот источник в degraded и требует обслуживания, вместо попыток найти обход.

**Интерфейсы:**

```python
class Collector(Protocol):
    source: str

    async def collect(
        self, criteria: SearchCriteria, client: "BoundedHttpClient"
    ) -> CollectionResult: ...


async def run_scheduler(
    collectors: Sequence[Collector],
    criteria: SearchCriteria,
    repository: SQLiteRepository,
    notifier: "Notifier",
    stop_event: asyncio.Event,
) -> None: ...
```

**Ограничения:** не использовать частные JSON endpoints, которые не представлены публичной поисковой страницей или официальной документацией. Корневой HTTP 200 не считать подтверждением доступности поиска.
