# Текущее состояние: 6 октября 2026

Основной монитор работает на VPS под systemd `rent-monitor`. Backend Авито — `home-pow`, исходящий маршрут — домашний ПК через обратный SSH-forward. Current указывает на отдельный каталог релиза в `/opt/rent-monitor/releases`; точную версию после развёртывания показывают `REVISION` и `readlink /opt/rent-monitor/current`.

## Путь запроса и доставки

1. Независимый runner Авито выбирает точную выдачу из конфигурации примерно каждые 60 секунд ±5.
2. `HomePowTransport` передаёт URL и referer постоянному worker через JSON-lines. Таймаут 120 секунд, зависший worker завершается и создаётся заново на следующей попытке.
3. Worker использует одну curl_cffi-сессию через `http://127.0.0.1:18782`. SSH доставляет CONNECT-запрос домашнему relay на `127.0.0.1:18781`.
4. Исходный HTML разбирают парсеры проекта с проверкой выдачи и фильтров. Рекомендации вне основной выдачи игнорируются.
5. Новые подходящие объявления обогащаются описанием и характеристиками. Между карточками 15 секунд, максимум пять за проход. Проверяется ID карточки и наличие описания. Уже сохранённые подробности используются повторно.
6. Данные и событие сохраняются в SQLite, Telegram получает текст через долговечную очередь. Фото и видео сейчас не входят в доставку.

База: `/var/lib/rent-monitor/rent-monitor.sqlite3`. Worker: `/opt/rent-monitor/home-route`. Приватное состояние: `/var/lib/rent-monitor/avito-home-pow`. Токен и owner-привязка сохранены с прежнего запуска. Первый снимок переключения — 49 карточек — был записан как baseline без отправки старых вариантов.

## Происхождение решения

Репозиторий [Avito-Parser](https://github.com/mickberrad659-sketch/Avito-Parser) предложил пользователь. Закреплён commit [2d09315](https://github.com/mickberrad659-sketch/Avito-Parser/tree/2d09315ead7ef1b3498415474f690eea512cf571). Оттуда используются защитные протоколы и HTTP-сессия. Исходный сбор электроники и его частота не перенесены. Чужой checkout устанавливается отдельно в игнорируемый `vendor`; здесь хранятся наши адаптер, worker и инструкции.

Практическая доработка: HTTP 439 возвращал HTML, а challenge отсутствовал в JSON. Скрипт страницы брал `pow_challenge` из cookie Авито и вызывал `/web/3/firewallPow/get` и проверку. Адаптер повторяет этот поток, устанавливает подтверждённый `pow_solved` на короткое время и повторяет исходный URL в той же сессии. Открытие одной выдачи само по себе не было принято за успех: отдельно проверены карточки и Telegram.

## Что проверено

Два живых прохода дали по 49 карточек; три разных объявления открылись с HTTP 200. Первый переход: 439 → PoW → 200. Извлечены описания 236, 170 и 95 символов и 24, 27, 26 характеристик. Конечный тест доставки: четыре снимка с интервалом 60 секунд, 41 подходящий вариант из 49, одно явно помеченное тестовое сообщение доставлено в существующий Telegram. Естественных новых событий за короткий интервал не было.

Проверены восстановление SSH-туннеля после разрыва, сохранение сессии между выдачей и карточкой, уничтожение зависшего worker, запрет сторонних URL и retry домашнего offline. Локальный набор после переноса: 68 тестов и 8 subtests прошли. Реальные QRATOR и GeeTest в этом испытании не возникали. Изменение защиты Авито может потребовать новой адаптации.

## Эксплуатация

[Команды и установка](../deploy/home-route/README.md). При выключении ПК источник получает `home_route_unavailable` и повторяется через 60 секунд, без часового backoff. Другие ошибки остаются видимыми в `/status`. Автоматический вход до авторизации Windows не настроен; задача запускается после входа пользователя. Экран может выключаться, автоматический сон блокируется пока supervisor работает.

Резервная копия первоначального переключения: `/opt/rent-monitor/backups/20261006-home-pow`. Прежний релиз: `/opt/rent-monitor/releases/20260930-firefox-recovery`. Откат кода не должен автоматически откатывать базу: это потеряло бы новые объявления и историю доставки.
