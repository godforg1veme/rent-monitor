# Как вносить изменения

Перед крупной доработкой сначала опишите ожидаемое поведение и затрагиваемые источники. Изменения сборщика одного сайта должны оставаться изолированными от остальных.

## Правила проекта

- Получать только публичные страницы поиска и карточек объявлений.
- Не добавлять авторизацию, cookies, прокси, скрытые API или обход CAPTCHA.
- При ограничении со стороны площадки останавливать этот источник и сохранять его статус.
- Не менять фильтр нулевой комиссии на эвристическое предположение.
- Не сохранять HTML, телефоны, профили и полные описания объявлений.
- Не добавлять токены, базы объявлений и локальные секреты в Git.

## Изменения в коде

Создавайте отдельную ветку от `main`. Старайтесь менять один логический слой за раз, придерживайтесь интерфейсов из `docs/superpowers/specs` и кратко опишите в pull request, что изменилось и какие ограничения источника остались.

Сообщения коммитов можно писать в форме `feat:`, `fix:`, `docs:` или `chore:` с коротким описанием.

## Локальная проверка

Установите закреплённые зависимости и выполните E2E-сценарий:

```powershell
uv sync --locked
uv run --locked python -m unittest discover -s tests/e2e -v
uv run --locked ruff check .
uv run --locked ruff format --check .
```

Сценарий работает только с фикстурами, SQLite в памяти и заглушкой Telegram. Не добавляйте к нему запросы к живым площадкам, токены или сохранённые страницы объявлений.
