# Как вносить изменения

Текущее устройство описано в [README](README.md) и [домашнем маршруте](deploy/home-route/README.md). Спецификации в `docs/superpowers` сохраняются как история решений.

Получаем публичные выдачи и карточки. Текущий режим использует домашний CONNECT-маршрут, временные cookies HTTP-сессии и адаптер проверки PoW. Изменения одного источника должны оставаться изолированными от остальных. Сетевой сбой домашнего маршрута повторяется через 60 секунд; ошибки структуры и защиты не должны превращаться в бесконечный частый цикл.

Обязательные фильтры проверяются по подтверждённым данным. Не подменяйте неизвестную комиссию нулевой. Полное публичное описание и характеристики сохраняются в SQLite. Диагностический HTML и challenge cookies остаются в закрытом runtime-каталоге с ограничением числа файлов. Не коммитьте реальные базы, переписку, HTML, cookies, токены или SSH-ключи.

Внешний Avito-Parser устанавливается отдельно на закреплённом коммите. Обновляя его, проверяйте отдельно выдачу, карточку и доставку, указывайте новую версию и результаты. Не переносите чужой исходный код в репозиторий без проверки условий использования.

```powershell
uv sync --locked
uv run --locked pytest tests/unit tests/e2e -q
uv run --locked ruff check .
uv run --locked ruff format --check .
```

Браузерные интеграционные тесты запускаются отдельно после установки Chromium. Тесты не должны обращаться к Авито или отправлять сообщения в настоящий Telegram. Для развёртывания сохраняйте SQLite и очередь доставки, используйте новый каталог релиза и возможность возврата. Не сбрасывайте baseline при обычном обновлении.

Коммиты: `feat:`, `fix:`, `docs:`, `chore:` с конкретным описанием. Синхронизация веток выполняется обычным merge/fast-forward и push, без переписывания опубликованной истории.
